# Component Sandbox Bundling & Package Hardening

**Date:** 2026-03-31
**Status:** Draft
**Repos affected:** `CSlate-shared`, `CSlate` (client)

---

## 1. Goal & Motivation

### The problem

Components generated by the agent currently break in two ways:

1. **Import resolution fails silently.** The `DynamicComponent` sandbox uses Babel + `new Function`. When `ui.tsx` imports `./hooks/useData`, Babel compiles it to `require('./logic')`. `require` doesn't exist in `new Function` scope, so the component fails with a cryptic error. The sandbox is fundamentally incompatible with multi-file component packages.

2. **The agent can write arbitrary filenames.** `writeComponent` and `renderComponent` accept open `files` objects with no structural enforcement. A misbehaving or prompt-injected agent could attempt to write `../../package.json` or pass `server.js` as a filename. Path traversal is blocked at the OS level, but the filename allowlist is missing.

### The solution

Two things, treated as one coherent design:

- **Structural enforcement at the package schema level.** `ComponentPackageSchema` in `@cslate/shared` gains minimum-viable validation (path safety, `ui.tsx` required). Both tools (`renderComponent`, `writeComponent`) call `validateComponentPackage()` before doing anything. Content is not policed — users can write whatever TypeScript they want.

- **Real bundling before eval.** `renderComponent` bundles all component files with esbuild (in-memory, virtual filesystem) before sending the result to the renderer. `DynamicComponent` evaluates the pre-built CJS bundle instead of running Babel on a single file. Relative imports between component files work. The component can have any directory structure a real TypeScript app would have.

## 2. Architecture Overview

### Current flow

```
Agent calls renderComponent({ files: { 'ui.tsx': '...' }, manifest })
  → main: renderComponent.execute()
      → stripFences(ui.tsx)
      → sender.send('sandbox:load', { files })   ← renderer ignores this (dead code)
      → returns { success, componentId }
  → ipc.ts: sender.send('agent:tool-call', { tool, input })
  → ipc.ts: sender.send('agent:tool-result', { tool, result })

Renderer:
  useChat.ts: agent:tool-call → capture input.files['ui.tsx'] as pendingCode
  useChat.ts: agent:tool-result (renderComponent, success) → setCurrentCode(pendingCode)
  SlateCanvas: reads currentCode from chatStore
  DynamicComponent: receives code prop (ui.tsx string)
    → Babel.transform(code, { presets: ['react'] })
    → new Function('React', 'useState', ..., transformedCode)
    → looks for `Component` variable
    → renders
```

Problems: single file only, no imports, `Component` naming constraint, Babel loaded lazily per render.

### New flow

```
Agent calls renderComponent({ files: { 'ui.tsx': '...', 'hooks/useData.ts': '...' }, manifest })
  → main: renderComponent.execute()
      → validateComponentPackage({ manifest, files })  ← returns errors or passes
      → stripFences(all files)
      → bundleComponentFiles(files)                    ← esbuild virtual FS, CJS output
      → returns { success, componentId, bundle, files }

  → ipc.ts: sender.send('agent:tool-result', { tool, result: { success, bundle, files } })

Renderer:
  useChat.ts: agent:tool-result (renderComponent, success)
    → setCurrentBundle(result.bundle)
    → setCurrentFiles(result.files)
    → setPublishState('prompting')
  SlateCanvas: reads currentBundle from chatStore
  DynamicComponent: receives bundle prop (CJS string)
    → CJS shim: module/exports/require(react → injected React)
    → new Function('require', 'module', 'exports', bundle)
    → module.exports.default is the component
    → renders
```

### 3.1 `ComponentPackageSchema.files` — add `superRefine`

Current:
```typescript
export const ComponentPackageSchema = z.object({
  manifest: ComponentManifestSchema,
  files: z.record(z.string()),
})
```

New — replace `files`:
```typescript
export const ComponentPackageSchema = z.object({
  manifest: ComponentManifestSchema,
  files: z.record(z.string()).superRefine((files, ctx) => {
    // Rule 1: ui.tsx is the entry point — required for any component to render
    if (!('ui.tsx' in files)) {
      ctx.addIssue({
        code: z.ZodIssueCode.custom,
        message: 'ui.tsx is required — it is the component entry point',
        path: ['ui.tsx'],
      })
    }

    // Rule 2: path safety — no traversal, no absolute paths, no null bytes
    for (const filePath of Object.keys(files)) {
      if (filePath.includes('..')) {
        ctx.addIssue({
          code: z.ZodIssueCode.custom,
          message: `Path traversal not allowed: "${filePath}"`,
          path: [filePath],
        })
      }
      if (filePath.startsWith('/')) {
        ctx.addIssue({
          code: z.ZodIssueCode.custom,
          message: `Absolute paths not allowed: "${filePath}"`,
          path: [filePath],
        })
      }
      if (filePath.includes('\0')) {
        ctx.addIssue({
          code: z.ZodIssueCode.custom,
          message: `Null bytes not allowed in path: "${filePath}"`,
          path: [filePath],
        })
      }
    }
  }),
})
```

**Rationale:** Intentionally minimal. Files are open (`z.record`) — any relative path is allowed. We only enforce the single invariant needed for the component to run (`ui.tsx`) and the security invariants (no traversal). Content is not policed.

### 3.2 `validateComponentPackage()` — new export

Add to `src/schemas/manifest.ts`:

```typescript
export type PackageValidationResult =
  | { valid: true; pkg: ComponentPackage }
  | { valid: false; errors: string[] }

export function validateComponentPackage(pkg: unknown): PackageValidationResult {
  const result = ComponentPackageSchema.safeParse(pkg)
  if (result.success) return { valid: true, pkg: result.data }
  const errors = result.error.issues.map(issue => {
    const path = issue.path.length > 0 ? `${issue.path.join('.')}: ` : ''
    return `${path}${issue.message}`
  })
  return { valid: false, errors }
}
```

### 4.2 `bundleComponentFiles(files)` — full implementation

```typescript
// src/main/agent/lib/bundler.ts
import * as esbuild from 'esbuild'
import * as nodePath from 'path'

/**
 * Bundles a component package's files into a single CJS string using esbuild.
 * Entry point is always ui.tsx. All relative imports are resolved from the
 * in-memory files map. react and react-dom are externalized (injected by sandbox).
 *
 * Throws if bundling fails (bad TypeScript, missing import, etc.).
 */
export async function bundleComponentFiles(
  files: Record<string, string>
): Promise<string> {
  const result = await esbuild.build({
    stdin: {
      contents: files['ui.tsx'],
      resolveDir: '/cslate-virtual',  // virtual root for relative import resolution
      loader: 'tsx',
      sourcefile: 'ui.tsx',
    },
    bundle: true,
    format: 'cjs',
    target: 'es2020',
    write: false,
    logLevel: 'silent',
    // React and react-dom are externalized — provided via the require() shim in DynamicComponent
    external: ['react', 'react-dom'],
    plugins: [virtualFilesPlugin(files)],
  })

  if (result.errors.length > 0) {
    const messages = result.errors.map(e => e.text).join('\n')
    throw new Error(`Bundle failed:\n${messages}`)
  }

  return result.outputFiles[0].text
}

/**
 * esbuild plugin that resolves relative imports from an in-memory files map.
 * Supports any directory depth. Tries .tsx, .ts, .jsx, .js extensions when
 * the import has no extension. Supports index file resolution.
 */
function virtualFilesPlugin(files: Record<string, string>): esbuild.Plugin {
  const VIRTUAL_NS = 'cslate-virtual'
  const VIRTUAL_ROOT = '/cslate-virtual'

  return {
    name: 'cslate-virtual-files',
    setup(build) {
      // Intercept relative imports from stdin (entry point)
      // stdin has namespace 'file' and resolveDir = VIRTUAL_ROOT
      build.onResolve({ filter: /^\./ }, (args) => {
        if (!args.resolveDir.startsWith(VIRTUAL_ROOT)) return undefined

        const relDir = args.resolveDir.slice(VIRTUAL_ROOT.length).replace(/^\//, '')
        const rawPath = relDir ? `${relDir}/${args.path}` : args.path
        const normalized = normalizePath(rawPath)
        const key = resolveFileKey(normalized, files)

        if (!key) {
          return {
            errors: [{
              text: `Module not found: "${args.path}" (tried "${normalized}" with .tsx/.ts/.jsx/.js extensions)`,
            }],
          }
        }
        return { path: key, namespace: VIRTUAL_NS }
      })

      // Intercept relative imports from within virtual files
      build.onResolve({ filter: /^\./, namespace: VIRTUAL_NS }, (args) => {
        const dir = nodePath.posix.dirname(args.importer)
        const rawPath = nodePath.posix.join(dir, args.path)
        const normalized = normalizePath(rawPath)
        const key = resolveFileKey(normalized, files)

        if (!key) {
          return {
            errors: [{
              text: `Module not found: "${args.path}" imported from "${args.importer}"`,
            }],
          }
        }
        return { path: key, namespace: VIRTUAL_NS }
      })

      // Load virtual files from the in-memory map
      build.onLoad({ filter: /.*/, namespace: VIRTUAL_NS }, (args) => {
        const content = files[args.path]
        if (content === undefined) {
          return { errors: [{ text: `Virtual file not found: "${args.path}"` }] }
        }
        return {
          contents: content,
          loader: getLoader(args.path),
        }
      })
    },
  }
}

/**
 * Normalizes a raw relative path by resolving . and .. segments.
 * Input: "hooks/../utils/format" → Output: "utils/format"
 */
function normalizePath(rawPath: string): string {
  const parts: string[] = []
  for (const part of rawPath.replace(/^\.\//, '').split('/')) {
    if (part === '..') {
      parts.pop()
    } else if (part !== '.' && part !== '') {
      parts.push(part)
    }
  }
  return parts.join('/')
}

/**
 * Resolves a normalized path to a key in the files map.
 * Tries: exact match, then .tsx/.ts/.jsx/.js extensions, then index files.
 */
function resolveFileKey(
  normalized: string,
  files: Record<string, string>
): string | null {
  // Exact match (path already has extension)
  if (files[normalized] !== undefined) return normalized

  // Extension resolution
  for (const ext of ['.tsx', '.ts', '.jsx', '.js']) {
    const candidate = normalized + ext
    if (files[candidate] !== undefined) return candidate
  }

  // Index file resolution
  for (const ext of ['.tsx', '.ts', '.jsx', '.js']) {
    const candidate = `${normalized}/index${ext}`
    if (files[candidate] !== undefined) return candidate
  }

  return null
}

/** Maps file extensions to esbuild loaders. */
function getLoader(filePath: string): esbuild.Loader {
  const ext = nodePath.extname(filePath).toLowerCase()
  const loaderMap: Record<string, esbuild.Loader> = {
    '.tsx': 'tsx',
    '.ts': 'ts',
    '.jsx': 'jsx',
    '.js': 'js',
    '.json': 'json',
    '.css': 'css',
  }
  return loaderMap[ext] ?? 'js'
}
```

### 4.3 What esbuild handles automatically

- TypeScript type stripping
- TSX/JSX transformation
- `import type` statements (erased)
- Re-exports (`export { x } from './y'`)
- Default and named exports → accessible via `module.exports.default` / `module.exports.name`
- Tree shaking (unused code removed from bundle)
- Circular dependency detection (will error clearly)

### 4.4 What esbuild does NOT handle (by design)

- npm package imports (e.g., `import _ from 'lodash'`) — these are NOT externalized and will cause a bundle error if the package isn't in node_modules. For sandbox components, all npm dependencies must be requested via bridge or be polyfilled. This is intentional: untrusted component code should not load arbitrary npm packages at runtime.
- CSS Modules — component CSS should use Tailwind classes
- Image imports — components should reference images via bridge

execute: async (input: RenderInput): Promise<RenderOutput> => {
  // Step 1: Strip markdown fences from all file contents
  const cleanFiles: Record<string, string> = {}
  for (const [path, content] of Object.entries(input.files)) {
    cleanFiles[path] = stripFences(content)
  }

  // Step 2: Validate package structure
  const validation = validateComponentPackage({ manifest: input.manifest, files: cleanFiles })
  if (!validation.valid) {
    return { success: false, componentId: '', errors: validation.errors }
  }

  // Step 3: Bundle all files with esbuild
  let bundle: string
  try {
    bundle = await bundleComponentFiles(cleanFiles)
  } catch (e) {
    const message = e instanceof Error ? e.message : String(e)
    return { success: false, componentId: '', errors: [`Bundle failed: ${message}`] }
  }

  // Step 4: Return success with bundle and files included
  const componentId = `comp_${Date.now()}`

  // Note: sandbox:load send is removed. Bundle is delivered to renderer
  // via the agent:tool-result IPC event (see ipc.ts). This eliminates the
  // previously dead sandbox:load path.

  return { success: true, componentId, bundle, files: cleanFiles }
},
```

execute: async (input: WriteInput): Promise<WriteOutput> => {
  // Step 1: Path containment — componentId must not escape components root
  const componentsRoot = resolve(projectDir, 'components')
  const componentDir = resolve(componentsRoot, input.componentId)
  if (!componentDir.startsWith(componentsRoot + sep)) {
    return { success: false, path: '', errors: ['Invalid componentId: path traversal detected'] }
  }

  // Step 2: Strip markdown fences
  const cleanFiles: Record<string, string> = {}
  for (const [path, content] of Object.entries(input.files)) {
    cleanFiles[path] = stripFences(content)
  }

  // Step 3: Validate package structure
  const validation = validateComponentPackage({ manifest: input.manifest, files: cleanFiles })
  if (!validation.valid) {
    return { success: false, path: '', errors: validation.errors }
  }

  // Step 4: Write all files
  await mkdir(componentDir, { recursive: true })
  await writeFile(join(componentDir, 'manifest.json'), JSON.stringify(input.manifest, null, 2), 'utf-8')

  await Promise.all(
    Object.entries(cleanFiles).map(async ([filePath, content]) => {
      const target = join(componentDir, filePath)
      // Double-check each file path stays within componentDir
      if (!target.startsWith(componentDir + sep)) {
        throw new Error(`Path traversal in files map: "${filePath}"`)
      }
      await mkdir(dirname(target), { recursive: true })
      await writeFile(target, content, 'utf-8')
    })
  )

  return { success: true, path: componentDir }
},
```

## 7. Part 5 — `DynamicComponent` Renderer Update

**File:** `src/renderer/sandbox/DynamicComponent.tsx`

### 7.1 What changes

- Remove `@babel/standalone` entirely (no more lazy import, no more `getBabel()`)
- Accept `bundle: string` prop instead of `code: string`
- Replace `compileCode()` with `evalBundle()` — evaluates a pre-built CJS string
- CJS shim: provide `require`, `module`, `exports` in `new Function` scope
- `require('react')` → returns injected React object
- `require('react-dom')` → returns injected ReactDOM object
- Any other `require()` call throws a clear error (not a cryptic ReferenceError)
- Default export (`module.exports.default`) is the Component

### 7.2 Full new implementation

```typescript
// src/renderer/sandbox/DynamicComponent.tsx
import React from 'react'
import ReactDOM from 'react-dom'
import { ComponentError } from './ComponentError'

interface Props {
  bundle: string  // Pre-built CJS bundle from esbuild (main process)
}

interface EvalResult {
  Component: React.ComponentType | null
  error: string | null
}

/**
 * Evaluates a pre-built CJS bundle in an isolated new Function scope.
 * Provides a require() shim that handles react and react-dom.
 * All other require() calls throw — no arbitrary module loading.
 */
function evalBundle(bundle: string): EvalResult {
  try {
    const _module = { exports: {} as Record<string, unknown> }
    const _exports = _module.exports

    const _require = (mod: string): unknown => {
      if (mod === 'react') return React
      if (mod === 'react-dom') return ReactDOM
      throw new Error(
        `Module "${mod}" is not available in the CSlate sandbox. ` +
        `Use bridge.fetch() for external data, or inline your logic.`
      )
    }

    // eslint-disable-next-line no-new-func
    const factory = new Function('require', 'module', 'exports', bundle)
    factory(_require, _module, _exports)

    // esbuild CJS output assigns the default export to module.exports.default
    const Component = _module.exports['default'] as React.ComponentType | undefined

    if (typeof Component !== 'function') {
      return {
        Component: null,
        error:
          'Component has no default export. ' +
          'Make sure your ui.tsx has: export default function MyComponent() { ... }',
      }
    }

    return { Component, error: null }
  } catch (e) {
    return { Component: null, error: `Failed to evaluate component: ${String(e)}` }
  }
}

class ErrorBoundary extends React.Component<
  { children: React.ReactNode; onError(e: Error): void },
  { caught: boolean }
> {
  state = { caught: false }
  static getDerivedStateFromError() { return { caught: true } }
  componentDidCatch(e: Error) { this.props.onError(e) }
  render() { return this.state.caught ? null : this.props.children }
}

export function DynamicComponent({ bundle }: Props) {
  const [result, setResult] = React.useState<EvalResult>({ Component: null, error: null })
  const [runtimeError, setRuntimeError] = React.useState<string | null>(null)

  React.useEffect(() => {
    setRuntimeError(null)
    // evalBundle is synchronous (bundle is already compiled)
    setResult(evalBundle(bundle))
  }, [bundle])

  if (result.error) return <ComponentError message={result.error} code={bundle} />
  if (runtimeError) return <ComponentError message={`Runtime error: ${runtimeError}`} code={bundle} />
  if (!result.Component) return null

  return (
    <ErrorBoundary key={bundle} onError={(e) => setRuntimeError(e.message)}>
      <result.Component />
    </ErrorBoundary>
  )
}
```

### 7.3 Key behavioral differences from Babel approach

| Aspect | Before (Babel) | After (esbuild CJS) |
|---|---|---|
| Compilation | Lazy, in renderer, per render | Eager, in main process, before tool returns |
| Multi-file support | No (single string) | Yes (all files bundled) |
| Component naming | Must be `Component` variable | Any name, must be default export |
| Import resolution | Fails silently | Works (esbuild resolved at bundle time) |
| Error messages | Cryptic Babel/eval errors | Clear esbuild diagnostics |
| `require()` unknown | `ReferenceError: require not defined` | Throws with actionable message |
| React availability | Injected as `new Function` parameters | Via `require('react')` shim |

### 7.4 `ComponentError` component

`ComponentError` currently accepts `{ message: string; code: string }`. The `code` prop is used for display (shows the source). With bundled output, `bundle` is minified CJS — not useful to display. Update `ComponentError` to accept `code` as optional or rename to `source`. For now, pass `bundle` as-is; a future improvement can show the original source from the store's `currentFiles`.

      <DynamicComponent bundle={currentBundle} />
    </div>
  </div>
)}

## 11. Part 9 — `PublishToast` Update

**File:** `src/renderer/chat/PublishToast.tsx`

### 11.1 Changes

`PublishToast` currently reads `currentCode` and publishes `{ 'ui.tsx': currentCode }`. With the new design, it reads `currentFiles` and publishes the full file set.

```typescript
const currentFiles = useChatStore((s) => s.currentFiles)

// In publish handler:
source: currentFiles ?? {}
```

This means the full component source (all files, not just `ui.tsx`) is submitted to the community server. This is the correct behaviour — the server's pipeline validates the complete package.

## 16. Edge Cases & Open Questions

| Topic | Decision |
|---|---|
| **CSS files** | esbuild handles `.css` loader but the CSS won't be injected into the DOM in a `new Function` context. For now, CSS files in components are bundled but styles won't apply. Future work: extract CSS and inject a `<style>` tag. Components should use Tailwind classes. |
| **JSON imports** | Supported by esbuild `json` loader — `import data from './data.json'` works. |
| **Large bundles** | If a user creates a very large component, the bundle string passed through IPC could be large. Electron IPC has no hard limit but very large payloads (>10MB) may cause performance issues. Not a concern for typical components. |
| **Bundle caching** | No bundle caching implemented. Every `renderComponent` call rebundles. esbuild is fast enough (~5ms for small components) that this is acceptable. |
| **Source maps** | esbuild generates source maps by default. Disable with `sourcemap: false` in the bundler to reduce bundle size. Error messages will reference compiled output, not source. Consider enabling source maps in dev mode only. |
| **`context.md` required?** | Not enforced by schema — it's optional in the files map. The agent skill prompt describes it as required, but the schema is lenient. |
| **Deprecate `sandbox:load` channel** | The channel is in `ALLOWED_SEND_CHANNELS` but was never used. Should be cleaned up in a future PR — out of scope here. |
| **@cslate/shared consumed by server** | CSlate-server doesn't yet consume `@cslate/shared`. Once it does, the server's Stage 1 (manifest validation) can use `validateComponentPackage()` directly. |
